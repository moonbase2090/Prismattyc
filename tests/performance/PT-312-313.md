# Streaming correctness and plain-output bookkeeping

## Changes

PT-312 preserves following ASCII when a UTF-8 scalar spans feed calls. A
fixed-size parser wrapper finishes the pending prefix before handing the
remaining buffer to bulk parsing. It allocates no buffers and inspects at
most three trailing bytes after a bulk call.

PT-313 skips the previous-cell ZWJ lookup when the existing cluster store is
empty. Every stored tail, including restored and copied tails, has a handle
in that store. Nonempty stores use the existing lookup. There is no new cache,
per-cell field, timer, configuration, or presenter effect. Once a screen has
stored clusters, the shortcut is unavailable until collection removes them.

## Correctness evidence

- The split-input regression failed before PT-312 and passed after it.
- 189 core and 133 emulator unit tests pass. New fixtures exercise UTF-8
  partitions, empty/malformed/incomplete feeds, wide and combining text,
  ZWJ/RI/modifier clusters, styles, hyperlinks, wrapping, history, resize,
  restored/copied cells, alternate screens, epochs, and damage.
- Core fixtures compare each scalar operation with the general lookup path.
- All 15 mutations intersecting changed runtime code are caught: 12 parser
  mutations and 3 core mutations. Six parser mutations initially survived;
  pending-prefix state tests caught them on a focused rerun. The six already
  caught parser mutations were reused because their code and tests stayed
  unchanged. Mutation baseline selectors executed 4 parser and 3 core tests.
- Private X11 captures show identical terminal pixels for whole and split
  `é é` on both the corrected baseline and the combined binary. The old
  release's split capture loses the space and differs from its whole capture.
  Comparisons exclude the 24-pixel title strip, whose activity indicator
  depends on input timing.
- All 60 paired PT-313 feed receipts have identical final text, cursor,
  retained history bytes, history line count, and cell size.
- Independent code review found no issues at `0bdbe791`.

## Performance evidence

These are local Linux CPU-presenter measurements, not cross-platform claims.
Release builds use Rust 1.90.0 on Ubuntu 22.04. Jobs run serially, with two
container CPUs, a 4 GiB runtime memory cap, private Xvfb/Openbox, JetBrains Mono
16 px, and default ligatures disabled. Source revisions are `9d0debce`
(corrected PT-312 baseline) and `1009abc` (PT-313 runtime change); later commits
only strengthen tests and document results.

Five alternating trials per case, 80 columns, 24 rows, 8 KiB feed chunks,
300,000 repetitions. Values are median MiB/s:

| Input | History limit | PT-312 | PT-313 | Change |
|---|---:|---:|---:|---:|
| ASCII | 0 | 65.24 | 79.93 | +22.5% |
| ASCII | 10,000 | 55.09 | 65.01 | +18.0% |
| ASCII | 100,000 | 54.57 | 63.97 | +17.2% |
| Wrapped ASCII | 0 | 65.72 | 80.11 | +21.9% |
| Wrapped ASCII | 10,000 | 55.90 | 67.70 | +21.1% |
| Wrapped ASCII | 100,000 | 56.28 | 67.69 | +20.3% |
| Escapes | 0 | 60.05 | 66.20 | +10.2% |
| Escapes | 10,000 | 43.48 | 46.36 | +6.6% |
| Escapes | 100,000 | 42.94 | 46.21 | +7.6% |

Initial Unicode medians were 0.7–3.9% lower. A longer confirmation used ten
alternating trials and 1.5 million repetitions at each history limit:

| History limit | PT-312 median (range) | PT-313 median (range) | Change |
|---|---:|---:|---:|
| 0 | 78.65 (77.43–79.16) | 77.53 (75.62–78.19) | -1.43% |
| 10,000 | 57.90 (56.41–59.05) | 57.75 (56.49–58.24) | -0.25% |
| 100,000 | 55.72 (55.18–56.18) | 55.47 (53.88–55.78) | -0.44% |

These ranges overlap; the measurements do not establish an exact zero cost
for the extra branch on complex text. The 100,000-row request is constrained
by the existing 96 MiB history byte budget.

The 100 native host trials cover idle, ASCII, Unicode, and paced repeated and
varying styled text with one and four panes. Median host CPU seconds:

| Workload | One pane PT-312 → PT-313 | Four panes PT-312 → PT-313 |
|---|---:|---:|
| ASCII | 0.39 → 0.33 | 1.46 → 1.22 |
| Unicode | 0.11 → 0.12 | 0.29 → 0.29 |
| Repeated text | 0.26 → 0.25 | 0.35 → 0.32 |
| Varying text | 0.32 → 0.32 | 0.34 → 0.35 |
| Idle | 0.00 → 0.01 | 0.01 → 0.01 |

ASCII host CPU falls 15–16%; other workload ranges overlap. Idle differences
are within the 10 ms process-accounting resolution and observed 0–20 ms range.
Maximum host RSS is 158.76 versus 158.79 MiB. No Cell layout change occurs.
PT-312 alone cost 0.7–2.6% in the earlier ASCII feed comparison against 0.2.19;
PT-313's measured gain exceeds that cost. The old release is not a correct
Unicode reference for split inputs.

## Reproduction

See [PROFILE.md](PROFILE.md) for the feed probe and measurement boundaries.
Run tests with `cargo test --locked -p prismattyc-core -p prismattyc-emulator
--lib`. Mutations are filtered to the changed lines and the `utf8_chunk_tests`
and `plain_output_tests` selectors; do not substitute a workspace mutation
run. Frozen binaries, hashes, scripts, raw timings, mutation outcomes, logs,
and native captures are retained under `build/pt312` and `build/pt313` in the
implementation worktree. Performance receipts cover Linux X11 only.
