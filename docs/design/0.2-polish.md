# Polish work before 0.2.0

## Release destination

At 0.2.0, publish Prismattyc from `Moonbase2090/Prismattyc` with a fresh
git history. The updater uses release versions and artifacts from that
repository. It never depends on ancestry, commit IDs, or a local checkout
of the development repository. This work does not migrate the repository
or publish 0.2.0 early.

## Work order and acceptance

1. Update and restart clarity. Download platform-specific release assets.
   Check provenance and digests before execution. Stage a complete version,
   switch it atomically, retain rollback, and serialize updates. Show installed
   and running component versions. Provide a coordinated restart and individual
   component choices. Never silently stop active sessions or local blank panes.
2. Scrollback reflow. Preserve logical lines and cursor placement when the
   primary terminal narrows or widens. Keep alternate-screen grid semantics.
   Cover wide glyphs, explicit line breaks, history limits, and copy behavior.
3. Interrupted Spaces operations. Prove helper cancellation and reaping, late
   write prevention, selection persistence, explicit save, status publication,
   dispatch, cache application, and idle current-Space inference.
4. Agent visibility (recommendation 5). Show pending mail and intentional
   pane-write receipts in the UI. Navigate to the exact target. Queued input
   must never be labelled as completed execution.
5. Accessibility and documentation (recommendation 6). Reconcile stale claims.
   Check keyboard navigation, exposed roles/actions, and theme contrast.
   Distinguish native screen-reader evidence from tree tests.
6. Sustained-load checks (recommendation 4, last by operator instruction).
   Run bounded isolated output, history, resize, and Space-switch workloads.
   Record responsiveness and memory over time. Preserve live operator sessions.

## Update and restart research

- [GitHub immutable releases](https://docs.github.com/en/code-security/concepts/supply-chain-security/immutable-releases):
  assemble a draft, attach every artifact, then publish the immutable release.
- [GitHub release asset API](https://docs.github.com/en/rest/releases/assets):
  release assets include size and SHA-256 digest metadata.
- [TUF overview](https://theupdateframework.io/docs/overview/): validate version
  progression, artifact identity, and complete sets; do not claim full TUF
  protection without implementing its signed metadata and expiry protocol.
- [systemd file descriptor store](https://systemd.io/FILE_DESCRIPTOR_STORE/):
  preserving open descriptors alone is insufficient; a restart must also
  preserve the service state that interprets them and process ownership.
